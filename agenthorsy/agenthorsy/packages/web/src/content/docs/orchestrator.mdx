The orchestrator is a top-level coordination layer that breaks complex user requests into subtasks, delegates each to an appropriate agent, and aggregates results. It runs transparently when a multi-step request is detected.

---

## Overview

When you submit a request that contains multiple actionable items, the orchestrator:

1. **Decomposes** the request into individual subtasks.
2. **Dispatches** each subtask to the best-fit agent via the Task tool.
3. **Aggregates** results from all agents into a final summary.
4. **Tracks** completion and failure history to avoid redundant work.

The orchestrator loop is defined in `src/orchestrator/orchestrator.ts` and is invoked automatically by the session prompt system.

---

## Task Decomposition

The `decomposeTasks()` function splits the user's message into subtasks using a sentence-level heuristic:

- The message is split on sentence-ending punctuation (`.`, `!`, `?`).
- Sentences shorter than 10 characters are discarded.
- Remaining sentences are checked for **action verbs** like `add`, `create`, `fix`, `refactor`, `update`, `build`, `deploy`, etc.
- Only sentences containing an action verb are kept as tasks.

If decomposition yields no tasks, the entire original query is treated as a single task.

### Example

```text
"Add user authentication. Fix the broken test in auth.spec.ts. Deploy to staging."
```

This decomposes into three tasks:

1. `Add user authentication`
2. `Fix the broken test in auth.spec.ts`
3. `Deploy to staging`

## Agent Types

The orchestrator works with several built-in agent types:

| Agent | Mode | Purpose |
|---|---|---|
| `build` | primary | Default agent with full tool access for development work |
| `plan` | primary | Read-only analysis and planning agent |
| `dynamic_persona` | primary | Autonomous agent spawned by the orchestrator for delegated tasks |
| `general` | subagent | General-purpose multi-step task execution |
| `explore` | subagent | Fast read-only codebase exploration |
| `compaction` | primary | System agent that compacts long context into summaries |

When the orchestrator needs to delegate a task and no existing agent matches, it spawns a new **dynamic_persona** child agent with its own worktree.

---

## Agent Dispatch

For each task, the orchestrator calls `findOrCreateAgent()` which follows a four-step resolution strategy:

### 1. Match by description

The orchestrator searches previously created agents for one whose description has significant keyword overlap (at least 2 non-stop-word matches) with the current task. If a match is found and the agent has not failed, the task is sent to that existing agent.

### 2. Match by todo context

If no description match is found, the orchestrator checks the todo items of active/completed agents. If a task's keywords overlap with a todo item's content, verification text, or file list, the task is routed to that agent.

### 3. Fallback to active child

If no match is found through description or todos, the orchestrator falls back to the most recently active child agent, reusing it for the new task.

### 4. Spawn new dynamic_persona agent

If no existing agent can handle the task, a new `dynamic_persona` agent session is created:

```typescript
const newChild = yield* sessions.create({
  parentID: orchestratorSessionID,
  title: `Dynamic Persona - ${task.slice(0, 50)}`,
  agent: "dynamic_persona",
})
```

Each new agent gets its own isolated worktree directory via the Worktree service.

## Result Aggregation

After all tasks complete, the orchestrator aggregates results into a summary stored in the session metadata:

```typescript
const aggregatedSummary = results
  .map((r, i) => {
    const text = extractText(r).slice(0, 500)
    return `Task ${i + 1} (${tasks[i]}): ${text}`
  })
  .join("\n\n")
```

The aggregated summary is persisted in `OrchestratorMetadata.lastAggregatedSummary` for reference in future interactions.

## Context Forwarding

Before each agent runs, the orchestrator injects context into the agent's message history via `applyOrchestratorReminders()`. This context includes:

- The task description and scope
- The expected outcome
- Previous task completion data (if the same agent handled an earlier task)
- Failure history from previous attempts

The directive is injected as an XML block in the agent's user message:

```xml
<orchestrator-directive>
Task: Add user authentication
Scope: src/auth/auth.ts
Expected outcome: Users can register and login
Before completing: update /architecture/ and /database_metadata/ if this task changed architecture or schemas.
</orchestrator-directive>

<failure-history>
You have previously failed this task 2 times. Latest failure reason: TypeScript error in auth.ts line 45
</failure-history>
```

## Completion Tracking

Each task is tracked in the orchestrator's session metadata with a `TaskRecord`:

```typescript
interface TaskRecord {
  id: string
  description: string
  agentID: string
  status: "pending" | "active" | "completed" | "failed"
  retries: number
  timestamp: number
  completionSummary?: string
  filesModified?: string[]
}
```

When the orchestrator re-runs (e.g., on session resume), it checks existing task records to avoid duplicating work. If a task with the same description and agent ID already exists, its status is updated rather than creating a duplicate.

---

## Compaction

After processing multiple tasks, the orchestrator may trigger automatic context compaction when the user message count reaches 4 or more. The compaction summarizes completed delegation cycles while preserving the most recent 2 cycles intact:

```text
Summarize the completed delegation cycles in this format:
- Task: [description] -> Agent: [agentID] -> Status: [completed/failed/retried]
```

This keeps the context manageable while retaining important recent history.

---

## Configuration

The orchestrator is controlled by the `default_agent` config setting. When a `dynamic_persona` agent is the default, the orchestrator handles all incoming requests. You can customize agent behavior through the `agent` config section:

```jsonc
{
  "agent": {
    "dynamic_persona": {
      "description": "Autonomous agent for full lifecycle tasks",
      "mode": "primary"
    }
  }
}
```
